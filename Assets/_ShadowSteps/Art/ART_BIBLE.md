# Shadow Steps — art bible (V2, top-down 2D)

**Camera:** strict top-down orthographic, portrait. One node = `nodeSpacing` world units (1.0 by default). Everything is a sprite on the XY plane; sorting order (see `BoardSorting`) decides stacking: edges < nodes < cones < route dots < props < ghosts < characters < arrows < overlays.

**Shape language (must stay readable at ~60 px per node on a phone):**
- Node: soft disc. Wall: rounded dark block with a light outline. Cover: diamond (passable cover is lighter than solid cover).
- Edge: thin bar between node centres; one-way edges carry a chevron; locked edges are amber until the key is held.
- Player: round cyan token. Guards: rounded squares, colour per mode (fixed red, rotate orange, ping-pong magenta, move-rotate violet, loop deep orange) **plus** a white facing arrow — never colour alone.
- Cones: translucent amber cells on exactly the nodes `VisionSystem` reports; high-contrast mode swaps the fill for a hatched cross glyph with higher alpha.
- Exit: green ring. Key: gold key glyph. Door: padlock, tinted open after the key.

**Palette:** cool navy floor (`BoardTheme.Background`, `Node`), teal interactables, amber danger, white indicators. All values live in `BoardTheme.asset`; nothing is hard-coded in views.

**Replacing placeholders:** every sprite field on `BoardTheme` is optional. Assign real sprites (power-of-two, 256 px per node recommended, pivot centre, PPU = texture size so one sprite = one node) and the procedural `SpriteFactory` shapes stop being used. Keep the silhouette rules above; decorations must never change traversal or visibility (they are not read by the simulation).

**Provenance:** all current art is generated in code (`SpriteFactory`), the app icon placeholder is generated by a script in the release step, and the audio is synthesised (`AudioService`). No third-party or copyrighted material is included.
