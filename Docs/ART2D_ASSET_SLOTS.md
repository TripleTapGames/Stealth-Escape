# Shadow Steps — 2D art slots (asset-ready structure)

Every sprite the 2D presentation draws comes from one ScriptableObject:
`Assets/_ShadowSteps/Art2D/SS2DSpriteLibrary.asset` (class `SS2DSpriteLibrary`). Gameplay never references a sprite;
`ShadowSteps2DRenderer` reads this asset at build time, so final art is dropped in by assigning sprites on the asset and
pressing Play. The placeholders are generated by `Shadow Steps ▸ 2D ▸ Generate board and object sprites`
(`SS2DSpriteGenerator`) and `▸ Capture character sprites` (`SS2DCharacterCapture`); running them again overwrites
only the placeholder PNGs in `Art2D/Sprites/` — any slot already pointing at your own asset elsewhere is left alone
if you remove it from the generator or keep your art outside that folder.

Conventions: 256 px per node spacing (`Pixels Per Unit` 256), centre pivot unless noted, no mip maps, bilinear,
uncompressed, sprite mesh Full Rect. Sizes in the table are the drawn size in node spacings (library "Geometry" fields).

## Final art (2026-11-03): courtyard background and directional characters

Hand-made PNGs live beside the placeholders and are wired by **Shadow Steps ▸ 2D ▸ Import final art** (`SS2DFinalArtImporter`,
batch entry `SS2DPrototypeSetup.ApplyFinalArtAndRender`). The importer never rewrites a PNG; it sets the `.meta` importer
(Sprite 2D and UI, single, transparency from alpha, no mip maps, bilinear, clamp, compressed) and assigns the library slots.
It is idempotent and runs again after the placeholder generator / character capture, so regenerating placeholders can
never hide the final art.

| Files | Importer | Library result |
|---|---|---|
| `Sprites/Backgrounds/Courtyard-Natural-Sides-1400x2000.png` | PPU 256, centre pivot, max 2048, Full Rect | `backgroundSprite`; `backgroundFit = FrameBoard` with `backgroundBoardRect` = the courtyard floor (x 0.277–0.709, y 0.344–0.712 from the bottom-left), `showBoardPanel = false`, `showFloorTiles = false` and `showPerimeterWalls = false` (the courtyard is the board surface; only nodes, paths, walls, cover, overlays and actors draw on it), camera clear colour = the painted water. The image is scaled **uniformly** so the floor encloses the tile grid, then only enlarged as far as needed to keep the 9:16 view covered; it is never stretched. Portrait rotation of wide levels is unaffected (the grid is framed after rotation). |
| `Sprites/Characters/Player/Suit-Faceless-{Up,Right,Down,Left}.png`, `Sprites/Characters/Guards/Blue-Guard-Faceless-{Up,Right,Down,Left}.png` (1024×2048) | PPU 2048, custom pivot (0.5, 0.363) = centre of the painted base disc, max 1024, Tight mesh | `spy` / `guard` facings in `Direction` order North = Up, East = Right, South = Down, West = Left; one still per facing used for both idle and walk (add more frames to the `walk` arrays for animation); `includesBase = true` hides the generated ring and shadow blob; `characterHeight = 1.5` (frame height in node spacings → base disc ≈ 0.68 spacing wide). The facing badge now sits just above the drawn sprite's top edge whatever its size. |

### Obstacle art and per-level decoration (2026-11-03)

| Files (`Sprites/Obstacles/`) | Importer | Library result |
|---|---|---|
| `obstacle bush.png` (2048², planter with baked shadow) | PPU 1000, pivot (0.515, 0.502) = planter box centre, max 1024, Tight | `bush`, `bushSize` 0.9 → box ≈ 0.84 spacing; used for authored X cells styled `BushPlanter` (and as `defaultObstacleArt` on levels without a layout) |
| `obstacle wall side.png` (vertical piece, pillar caps 1000 px apart) | PPU 1000, pivot (0.50, 0.60) = midpoint between the pillar caps | `wallSide`: a one-cell stone wall drawn vertically |
| `obstacle wall front.png` (horizontal piece, pillars 1000 px apart) | PPU 1000, pivot (0.518, 0.61) = centre of the top face | `wallFront`: a one-cell stone wall drawn horizontally; its front face hangs ≈ 0.5 spacing below the cell |

`SS2DLevelArtLayout` (`Art2D/LevelArt/SS2DArt_<code>.asset`, registered in the library's `levelArt` list, looked up by
stage code) is pure presentation: per authored X cell an art kind (BushPlanter / StoneWall / Crate), the logical axis a
stone piece runs along, an offset, a scale and a sorting offset; per camera id a mount preference (Auto / StoneWall /
Pole / Plate) with offset. The renderer rotates everything with the board and picks `wallSide` or `wallFront` from the
*drawn* axis, so a run along logical Y becomes a front piece on a rotated level. Blocked cells, camera cells and
facings always come from the V4 data; the layout cannot add or remove them. Stone camera mounts place the wall piece
along the mounting wall with its body flush with the wall face (side piece: 0.36 behind the face; front piece: 0.5 /
0.15 depending on which way the face points), the camera bracket + head + lens sit on the face as before.

Interior `#` walls (`interiorWallArt` = StoneWall): runs of adjacent interior wall cells draw one stone piece per cell
along the run (a run with a camera is slid `wallRunCameraHug` spacings toward the camera's face, so the camera sits on
the stone), lone interior walls draw the bush planter; boundary walls stay hidden over the painted courtyard.

Colours (background, accents, hazards, HUD-independent) and timings (`moveDuration`, `successBeat`, `doorWalkDuration`,
`doorOpenDelay`, `doorEnterDuration`, `doorCloseDelay`, `autoAdvanceAfterDoor`) are fields on the same asset.

## Scene structure (standard level)

`SS2DPrototypeSetup.CreateLevelScene(code)` writes `Art2D/Levels/SS2D_<code>.unity` with the same composition as the
vertical slice `Art2D/Demo/ShadowSteps_2D_Prototype.unity`:

- `GameSceneComposer` (Use2DArtPresentation, Art2DLibrary, HudPrefab = `Art2D/Prefabs/SS2DHud.prefab`, DebugStageId = the stage) — in Play mode this builds the session, input, the hidden placeholder board and the HUD; `SS2DSessionBridge` attaches and builds the 2D renderer; `GameFlowController` attaches the pause/results/failure screens and records progress.
- `SS2D_Prototype_Board`: `ShadowSteps2DRenderer` + `SS2DPreviewController` — edit-mode preview only (clears itself in Play mode).
- `Main Camera` with `SS2DCameraFitter` (frames the board panel plus the door between the HUD bands).
- `HUD`: `SS2DHudCanvas` preview (play mode uses the prefab instance the composer creates).

Prefabs: `Art2D/Prefabs/SS2DHud.prefab` (HUD; its canvas hierarchy is generated in `Bind`).
